# 脚本质检清单 V4：故事先行

## 检查顺序

1. 先运行硬质检器。
2. 硬错误为 0 后，再做创意质检。
3. 提取口播台词形成匿名副本，不读取原稿自评分、胜出理由和分镜解释。
4. 按 `story-first-production-rules.md` 与 `comedy-red-team.md` 审查事件链和裸台词。
5. 最后记录一个最大问题；没有具体问题不能判定通过。

## 硬质检

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/validate-script.ps1 -Path outputs/scripts/Sxxx-file.md -Strict
```

以下任一项出现即不能通过：

- 标称时长与分镜终点相差超过 5 秒。
- 分镜超过 90 秒。
- 超过 4 个主要角色。
- 超过 24 个镜头；严格模式下超过 18 个镜头。
- 缺少口播台词版、时间轴或具体问题。
- 文本写“通过”但硬指标存在错误。

## 创意质检

创意质检不使用百分制。结构合格不等于有趣，最终只给证据和判定。

### 火影锚点
- 去掉角色姓名后，脚本是否仍必须依赖火影能力、关系或旧账？
- 原著设定是在制造冲突，还是只负责换名词？
- 是否混用了不兼容的时期、身份或关系？

### 角色行为
- 每个角色为什么在现场？
- 角色会主动这么做，还是编剧需要他这么做？
- 第三人是否只补决定性事实，没有开启新支线？
- 台词互换后是否仍然成立？如果成立，口吻不够具体。

### 事件和笑点
- 3 秒内是否抛出冲突？
- 是否先发生了角色主动的错误执行，而不是先解释设定？
- 是否至少两次通过新行动把现场推向更糟处境？
- 每次升级是否围绕同一个问题，并改变了现场状态？
- 对每一次升级，能否明确回答“这个角色为什么会在此刻做这一步”？若答案只是“为了让局面更大”，判定为无因果升级。
- 是否有可演的沉默、后退、抢道具或解除忍术等视觉笑点？
- 结尾是否用动作或短句结束，而不是总结？
- 结尾是否让前面错误执行的代价以动作、关系或现场状态落地？
- 删除中间任一升级后，结尾是否会失去因果？如果不会，判定扩写失败。
- 最强句能否原封不动放进严肃同人？如果能，且没有荒唐行为和丢脸对象，判定不是喜剧包袱。
- 能否明确回答“谁因什么荒唐行为当场丢脸”？不能回答时判定喜剧负载不足。

### 去模板化
- 是否重复近期脚本的完整台词或辩解骨架？
- 是否机械包含“质问、证据、嘴硬、第二证据、旁人补刀”全部步骤？
- 不需要证据的题是否被强塞档案、报告或账单？
- 是否过度依赖 F008 旧账证据反杀？

### 拍摄执行
- Avatar、地图和关键道具是否在库存中可用或有替代？
- 是否 1 个主场景、12-18 个镜头即可完成？
- 特效是否有音效、出入画或反应镜头替代？
- 台词、动作和镜头是否能在标称时间内完成？

## 结论

- `通过`：硬错误为 0、红队判定 `advance`、完整事件具有错误执行、两次行动升级和可见结算，并已写最大风险。
- `需改写`：硬错误可修复，或红队判定 `trim`。
- `重写`：红队判定 `rebuild`，或触发定位、行为、资源、现代换皮一票否决。

即使通过，也必须在“主要问题”中写出最值得优化的一项。
