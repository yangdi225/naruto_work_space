# 故事红队 V3

## 输入隔离

红队只读取：

- 匿名编号。
- 口播台词。
- 目标时长。

红队不得读取候选排名、公式编号、胜出理由、自评分、作者解释和预设结论。拍摄资源在台词胜出后单独检查。

## 审查顺序

1. 用四格复述事件：错误执行 -> 升级行动一 -> 升级行动二 -> 可见结算。任一格只能写“解释设定”时直接失败。
2. 写出角色每次主动做了什么，而不是只标记新信息。
3. 指出最强包袱及其台词或动作位置，并说明它改变了谁的现实处境。
4. 做角色替换测试：换成普通同事或陌生人后仍成立则降级。
5. 做严肃同人测试：最强句放进严肃剧情是否仍完全自然。
6. 做停止行动测试：把主角在中段的行动拿掉，事件是否仍会自然滚大？会则说明升级是作者解释，不是人物驱动。
7. 做因果跳跃测试：逐个写出每次升级中“谁为什么会做下一步”。任何一步只能回答“为了让剧情更大”时直接失败。
8. 明确喜剧负载：谁因什么荒唐行为当场丢脸，观众为什么会笑而不只是觉得有道理。
9. 最后才给判定，不给百分制总分。

## 硬判定

出现任一项即淘汰或重建：

- 前两句没有异常行为或明确阻力。
- 没有具体欲望、错误执行、两次行动升级或可见结算中的任一项。
- 最强包袱不伤及身份、关系、欲望或即时损失。
- 最强句只是伤感揭露、关系控诉、正确观点或锋利总结，没有荒唐行为和丢脸对象。
- 最强句可以原封不动放进严肃同人剧情。
- 中间三分之一整体可删除，或删除后事件仍会自然到达原结尾。
- 结尾只给概念判断、没有新的可见处境。
- 关键升级依赖旁人无动机地做危险、极端或仅为配合笑点的行为。
- 笑点依赖标题、分镜说明、音效或作者解释才能成立。

## 输出字段

- `event_ladder`
- `character_actions`
- `visible_settlement`
- `peak_moment`
- `removable_action_or_line`
- `naruto_specificity`
- `comedy_payload`：荒唐行为、丢脸对象、发笑原因。
- `serious_drama_test`：pass / fail。
- `verdict`：`advance` / `trim` / `rebuild` / `reject`
- `single_biggest_problem`

同批比较时只选一个 `advance`。没有候选通过喜剧负载与严肃同人测试时，整批淘汰，不为完成任务硬选冠军。
