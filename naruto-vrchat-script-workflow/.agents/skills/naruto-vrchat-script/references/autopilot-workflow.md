# 自动驾驶流水线 V4：故事先行

## 目标

把候选竞争和失败改写放在内部完成。默认只向用户交付一条正式成品，不要求用户逐轮调试。

## 快速生产（默认）

1. 读取 `knowledge/taste-profile.md`、历史评价、选题池和拍摄库存。
2. 内部生成 5 个荒唐事件前提，先检查具体欲望、错误执行、身份代价和拍摄可行性，至少淘汰 3 个。
3. 为两强各写行动阶梯：错误执行 -> 升级行动一 -> 升级行动二 -> 可见结算。
4. 隐去标题、公式、角色热度、自评分和创作解释，按 `story-first-production-rules.md` 与 `comedy-red-team.md` 盲审事件链。
5. 只扩写冠军为 60-90 秒完整事件版；检查每个段落是否带来新行动或后果。
6. 通过后制作 VRChat 分镜，运行一次严格校验；仅在用户要求时另做 20-40 秒剪辑版。
7. 面向用户只交付冠军、一个最大风险和四标签反馈入口。

快速模式不创建长篇 `APxxx` 锦标赛 Markdown，不重复运行校验器。只在冠军选题和脚本记录中保存一句胜出依据。

## 深度生产（按需）

仅在用户明确要求“深度筛选”、批量策划或需要审计候选过程时，使用 `12 个候选 -> 4 个冷开场 -> 2 个扩写 -> 1 个冠军`，并保存完整生产记录。

## 用户指定选题

- 不再要求用户先看两个冷开场。
- 内部生成两个结构不同的行动阶梯，盲审后只扩写冠军。
- 用户明确要求看备选时才展示落选版本。

## 失败处理

- 单条被标记 `一般`：记录问题，下一条内部降低相同机制优先级，不启动人工校准。
- 单条被标记 `无聊` 或 `奇怪`：记录失败机制，下一次快速生产时禁用同类，不在当前请求内自动生成第二份长稿。
- 最近连续 3 条获得 `无聊` 或 `奇怪`：暂停成品生产，进入 6 条冷开场人工校准。
- 用户明确要求校准时可立即进入校准模式。

## 停止条件

- 每次请求最多进行 1 次台词压缩和 1 次硬质检，防止无限自我循环。
- 无法通过红队或硬质检时标记 `needs_rewrite` 并停止，不交付“最接近但并不好笑”的伪成品。

## 用户反馈成本

默认只请求一个标签：

- `保留`：方向成立。
- `一般`：能看但不突出。
- `无聊`：缺少喜剧压力或新信息。
- `奇怪`：角色、因果、时期或口吻不自然。

具体最好笑台词和泄气位置均为可选，不作为用户必须填写的字段。
