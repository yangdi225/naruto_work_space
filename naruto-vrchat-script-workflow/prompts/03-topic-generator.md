# Prompt 03 - 故事先行候选赛 V4

生成选题时读取账号定位、口味画像、组件系统、角色规则、已有选题、脚本评价和拍摄库存。本 Prompt 的详细输出默认保存为内部生产记录，不直接要求用户审阅。

## 输入
- 角色范围：
- 期望时长：完整事件版默认 60-90 秒
- 近期禁用主题：
- `knowledge/topic-pool.csv`：
- `knowledge/script-evaluations.csv`：
- `knowledge/production-inventory.csv`：
- `knowledge/taste-profile.md`：

## 流程
1. 按 `candidate-selection-rules.md` 默认生成 5 个事件候选。
2. 每个候选先写具体欲望、错误执行、升级一、升级二和可见结算；C/N/P/F 仅作复盘标注。
3. 检查重复、现代换皮、行为可信度和真实拍摄库存。
4. 至少淘汰 3 个，并写明淘汰原因代码；不使用百分制。
5. 两强各写一条行动阶梯和 8-12 句关键裸台词。
6. 隐去标题、公式、角色热度、自评分和创作解释，按 `comedy-red-team.md` 盲审事件链。
7. 只选一个冠军进入完整事件扩写；没有候选通过事件链和严肃同人测试时整批重建，不硬选。

## 喜剧校准模式

当最近连续 3 条被标记为无聊或奇怪，或用户明确要求校准时，读取 `comedy-intensity-rules.md`：

- 暂停完整脚本和冠军推荐。
- 生成 6 条机制不同的 15-20 秒纯台词冷开场。
- 每条必须有明确欲望、即时损失、羞耻目标和第二个新信息。
- 不输出公式、自评分、排名或创作解释。
- 必填只收集最想继续看哪条；其他具体反馈为可选。

## 约束
- 禁止用总分、爆款概率或“感觉更好”作为晋级理由。
- 关键库存为 `unknown` 时标记 `inventory_risk`。
- F008 当前处于冷却，除非用户明确要求，不作为主要旧公式。
- 用户指定选题时，内部写两个冷开场并扩写盲审，不要求用户选择。

输出使用 `templates/topic-generation-template.md`。
