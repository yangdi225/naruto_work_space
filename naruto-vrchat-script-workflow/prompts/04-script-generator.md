# Prompt 04 - 故事先行完整事件生成器 V4

只处理故事红队冠军。用户明确指定选题时，先比较两个行动阶梯，但只扩写胜出版。

## 输入
- 选题编号 / 标题：
- 冠军行动阶梯：
- C / N / P 组件（仅记录）：
- 旧公式来源：
- 角色与时期：
- 一句话冲突：
- 结尾机制：
- 目标时长：默认 60-90 秒
- 拍摄库存：
- 口味画像：

## 扩写阶段
- 对照冠军行动阶梯执行 `story-first-production-rules.md`。
- 先写完整事件版：错误执行、升级一、升级二和可见结算都必须以角色行动发生。
- 每段都要比上一段多一个可见麻烦、角色阻力或身份代价；不允许只延长问答。
- 删除任一升级后仍能接到结尾时，判定扩写失败。
- 用户明确要求短版时，另从完整事件剪出 20-40 秒版，且保留至少一次升级和可见结算。

## 正式脚本阶段
- 3 秒内进入异常行动或明确阻力。
- 允许事件横向扩展到 1-2 个场景，但每次转场必须让局面更糟。
- 台词默认 6-18 字，超过 30 字必须拆分。
- 角色口吻遵循 `character-voice-bank.md` 的思考与反应约束，不照抄万能句式。
- 至少有一个纯表演笑点。
- 证据道具按需使用，不为完成骨架强塞报告、档案或第三人。
- 默认 2-4 个角色、1-2 个场景；镜头数服从目标时长。
- 关键资源必须是 `available`、`substitute`，或明确标出 `unknown` 风险。
- 时间轴终点与标称时长相差不超过 5 秒。

## 禁止
- 严肃解说或设定科普。
- 现代行政流程主导冲突。
- 连续复用“那叫……”“功能上没问题”等近期辩解骨架。
- 为了二次打脸不断加入无关角色。
- 结尾写检讨、宣布处理或继续解释。

输出使用 `templates/script-output-template.md`。

保存后必须运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/validate-script.ps1 -Path <脚本文件> -Strict
```

硬错误不为 0 时先改写，不能写“通过”。
