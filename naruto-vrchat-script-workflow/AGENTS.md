# Codex 项目规则

## 定位

本项目生产火影 VRChat 沙雕短视频选题和拍摄脚本。角色必须在原著身份、能力和关系逻辑中现场吵起来；不要写成剧情解说、设定科普或现实段子换皮。

## 默认模式

用户要求生成选题或脚本时默认走 V4 故事先行模式：内部先比较 `5 个荒唐事件前提 -> 2 个升级阶梯 -> 1 个完整事件版`，再按需要剪短。默认交付 60-90 秒完整事件版，不创建长篇候选赛记录或要求用户逐轮选择；用户明确要求短版时，才交付 20-40 秒剪辑版。

## 生成前

1. 读取 `.agents/skills/naruto-vrchat-script/SKILL.md` 并按任务路由加载相关参考。
2. 读取 `knowledge/taste-profile.md`，服从已验证偏好，不把单次假设当永久规则。
3. 读取 `knowledge/topic-pool.csv`，避免重复核心冲突。
4. 读取 `knowledge/script-evaluations.csv`，优先吸收用户真实反馈。
5. 读取 `knowledge/production-inventory.csv`，不要假设 Avatar、地图或道具可用。
6. 先确定具体欲望、错误执行、两次行动升级、身份代价与可见结算；C/N/P/F 只在成稿后记录来源，不得反向限定故事。

## 脚本要求

- 默认先写 60-90 秒完整事件版；短版必须从完整事件剪出，不能为了短而删掉升级。
- 默认 2-4 个角色、1-2 个场景；镜头数服从事件，而非固定公式。
- 先输出口播台词版，再输出 VRChat 正反打分镜。
- 3 秒内进入异常行动或明确阻力。
- 中段至少两次通过新行动让局面更糟，不能只用问答解释设定。
- 角色口吻来自思考方式和反应速度，不复用万能句式。
- 证据道具按需使用，不强塞报告、档案、账单或 VCR。
- 第三人只在确有必要时补决定性事实，不开启新支线。
- 结尾用短句、动作代价或身份回旋结束，不写检讨或流程处罚。
- 结尾必须让身份代价落地为可见状态变化，不能只给一句概念定义。
- 允许档案、玩偶、清单和第三人，只要它们每次出现都会改变事件走向。

## 硬质检

保存新脚本或改写脚本后必须运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/validate-script.ps1 -Path outputs/scripts/Sxxx-file.md -Strict
```

- 硬错误不为 0，不能判定通过。
- 标称时长和分镜终点相差不能超过 5 秒。
- 独立质检只看匿名裸台词，忽略原稿自评分、胜出理由和分镜解释，必须指出至少一个具体问题。
- 创意质检不使用百分制证明好笑，也不以固定翻面位置或台词序号证明好笑。
- 故事红队必须确认存在“错误执行 -> 两次升级行动 -> 可见结算”；缺一项直接重写。
- 质检完成后更新脚本状态；“生成过”不等于“可拍”。

## 数据闭环

- 候选和淘汰原因写入 `knowledge/topic-pool.csv`。
- 用户反馈默认只收集 `保留 / 一般 / 无聊 / 奇怪`，写入 `knowledge/script-evaluations.csv` 的 `user_label`；详细台词反馈为可选。
- 得到明确反馈的脚本写入 `knowledge/script-retrospectives.md`。
- 只有硬质检通过且用户决定保留，状态才能进入 `shoot_ready`。
- 只有真实发布后才填写播放、完播、点赞和评论数据，禁止编造。
- 连续 3 条为 `无聊` 或 `奇怪` 才进入人工校准；单条失败记录机制，下一次生产禁用同类，不在当前请求内继续生成长稿。

## 文件规则

- 使用 UTF-8；遵守 `.editorconfig`。
- 保留已有 S/T/F 编号，不覆盖旧内容。
- 旧脚本可以保留为历史草稿，不因新规则批量伪装成通过。
